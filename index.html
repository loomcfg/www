Configuration woven for humans, compiled cleanly to JSON.

Loom (.loom) eliminates YAML's implicit type traps and TOML's deep-nesting boilerplate. Write strict, comment-rich configs with lightweight @tag types and deterministic @import composition.

Engineered to fix everyday config friction

Designed from first principles for application settings, CLI tools, and deterministic DevOps manifests.

{}

100% JSON-Isomorphic

Every .loom file evaluates to standard JSON objects, arrays, strings, numbers, booleans, and null—zero custom runtime required downstream.

@

Lightweight Type Tags

Annotate durations (@dur "15s"), dates (@date), instants (@instant), and regexes without breaking JSON round-trip compatibility.

...

Bounded Composition

Share presets via relative @import and shallow ...spread overrides without Turing-complete loops, side effects, or network fetches.

#

Lossless CST Edits

A Concrete Syntax Tree (CST) preserves comments, blank lines, and key ordering during both loom fmt and automated CLI mutations.

""

Zero Coercion Surprises

Strings always require quotes. Unquoted no, on, or 3.10 will never silently morph into booleans or truncated floats.

✓

JSON Schema Native

Link any standard JSON Schema with @schema for instant IDE autocomplete, hover docs, and CI validation out of the box.

How Loom compares

Ergonomic authoring without sacrificing strictness or ecosystem compatibility.

Capability Loom (.loom) JSON YAML TOML
Comments (# & /* */) Yes (preserved in CST) No Yes (# only) Yes (# only)
Implicit type coercion traps None (syntax-typed) None Yes (no, on, octal) None
Deeply nested arrays & objects Clean braced blocks Clean Indentation-fragile Verbose [[a.b.c]]
Modular reuse (@import / spread) Built-in & acyclic No Anchors only (same file) No
